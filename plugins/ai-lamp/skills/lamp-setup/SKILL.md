# AI通知ランプの設定と確認

このプラグインは、Claude Code のフックから USB ランプに状態を送る。
色は 3 つ: 作業中=青（ゆっくり明るくなったり暗くなったり）/ 完了=緑の点灯 / あなたの出番（許可・質問・エラーで止まった）=橙の点滅。
v0.5 から、エラーも橙にまとめた（Claude Code と Codex で色の意味をそろえるため。赤は使わない）。
ランプの先の**タッチ**（光る所のまわり）に触れると、どの状態でも消える（設定は消えない）。お客さんに話すときも「タッチ」と呼ぶ。（試作機の LED テープ版は光り方が少し違い、触る代わりに BOOTSEL ボタン）

ユーザーは機械に詳しくないことが多い。専門用語を避け、やさしい日本語で説明する。
このファイルは Windows 版（Mac 版は別のプラグイン）。

## スクリプトの場所
- 送信: `${CLAUDE_PLUGIN_ROOT}/scripts/lamp.ps1 <work|done|ask|error|end|seen>`
- 画面の見張り: `${CLAUDE_PLUGIN_ROOT}/scripts/lamp-watch.ps1`
- 見張りの自動起動 ON: `${CLAUDE_PLUGIN_ROOT}/scripts/watch-install.ps1`
- 見張りの自動起動 OFF: `${CLAUDE_PLUGIN_ROOT}/scripts/watch-uninstall.ps1`
- 状態の記録: `%USERPROFILE%\.cache\ai-lamp\state.json`（`sent` が最後にランプへ送った状態、`port` が見つけた COM ポート）

PowerShell スクリプトは `powershell -NoProfile -ExecutionPolicy Bypass -File "<パス>" <引数>` で実行する。

## ランプがつながっているか確かめる（まずこれを使う）
`${CLAUDE_PLUGIN_ROOT}/scripts/lamp-test.ps1` を実行する。ランプを探して、見つかれば 2 秒緑に光らせて消し、結果を日本語 1〜2 行で表示する。
**表示された結果を、そのままユーザーに伝える**（自分で COM ポートを調べて判断しない。調べ方を誤って「つながっていない」と言ってしまった例がある）。

## ランプが光らないとき（上から順に確認）
0. **まず記録を見て切り分ける**（お客さんの操作は要らない。読むだけ）: `%USERPROFILE%\.cache\ai-lamp\events.log` の最後の 10 行ほどを読む。会話の中身は書かれていない（合図の種類・会話番号の先頭・結果・時間だけ）。
   - 光らなかった時刻の行が**増えていない** → AI からの合図が出ていない。アプリを「×」でなくメニューの「終了」で閉じて開き直したか、新しい会話で試したか、（Codex は）フックを承認したかを確かめる
   - 行はあるが `send=NG(...)` → 合図は出ているが、ランプに届いていない。下の 1 から確かめる
   - `send=ok(...)` なのに光っていない → ランプ本体か USB の口の問題のことがある。別の USB の口に挿してもらう
1. ランプが USB に挿さっているか。挿し直すと虹色が流れれば本体は正常。`lamp-test.ps1` で確かめる。
2. `state.json` を読み、`port` と `sent` を確認する。`sent` が空（null）ならランプが見つかっていない。
3. ランプへの送信を試す: `lamp.ps1 done` を実行し（stdin は空でよい）、緑になるかユーザーに聞く。
   手で試したあとは `state.json` を削除して記録を消す（`default` という試験用の記録が残り、本物の表示を邪魔するため）。
4. 他のソフト（Arduino IDE のシリアルモニタなど）が同じ COM ポートを開いていないか。開いていると送れない。
5. それでもだめなら、デバイスマネージャーの「ポート (COM と LPT)」にランプが出ているかを見てもらう。

## 光り方を変えて と言われたら（色・光り方・明るさ）
スクリプトは書き換えない。**好みのファイル `%USERPROFILE%\.cache\ai-lamp\colors.json` だけ**を書き換える（無ければ作る。UTF-8 の JSON）。
```json
{
  "brightness": 50,
  "work": { "color": [128, 0, 255], "mode": "breathe" },
  "done": { "color": [255, 255, 255], "mode": "solid" },
  "ask":  { "color": [255, 0, 0], "mode": "blink" }
}
```
- `work`＝作業中、`done`＝完了、`ask`＝あなたの出番。書かなかった状態は、いつもの色（青・緑・橙）のまま
- `color` は赤・緑・青の強さ（各 0〜255）、または `"rainbow"`（虹色が流れ続ける）。`mode` は `solid`（点灯）／`breathe`（ゆっくり明るくなったり暗くなったり）／`blink`（点滅）／`fastblink`（激しい速い点滅）
- `"rainbow"` と `fastblink` はランプのファーム v1.0 から（`ID?` の返事が `AILAMP 1.0` 以上）。古いランプでは色が変わらないので、そのときは「ランプが古い版のため、この光り方は使えません」と伝える
- `brightness` は全体の明るさ（1〜100、％）。書かなければ最大
- ほかに使える項目（どれも、頼まれたときだけ書く。書かなければ使わない）
  - **夜は暗く**: `"night": { "from": "22:00", "to": "07:00", "brightness": 20 }`（その時刻の間だけ明るさを変える。日をまたいでよい。色が変わるときに反映されるので、夜に入っても点きっぱなしの色はそのまま）
  - **終わったときにお祝い**: `"celebrate": true`（返事が終わった瞬間に 1.5 秒だけ虹色が光ってから、完了の色になる）
  - **長い作業の目安**: `"long_work": { "minutes": 10, "color": [160, 0, 255] }`（作業中がこの時間続いたら、作業中の色をこの色に変える）
  - **AI ごとに色を分ける**: `"codex": { "work": { "color": [255, 0, 255], "mode": "breathe" } }`、`"claude": { ... }`（その AI のときだけ使う色。書いていない状態はふつうの色）
  - お祝い・長い作業は、ランプのファーム v1.1 から（`ID?` の返事が `AILAMP 1.1` 以上）。虹色・速い点滅は v1.0 から
- **おまかせセット**（「やさしい光り方にして」などと頼まれたら、このとおりに書く。今の設定は上書きしてよいか一言確かめる）
  - **いつもの**: ファイルを消す
  - **やさしい**: `{ "brightness": 40, "work": { "color": [0, 80, 255], "mode": "breathe" }, "done": { "color": [0, 255, 60], "mode": "breathe" }, "ask": { "color": [255, 140, 0], "mode": "breathe" } }`（全部ゆっくり、暗め）
  - **派手**: `{ "brightness": 100, "work": { "color": "rainbow", "mode": "solid" }, "ask": { "color": [255, 0, 0], "mode": "fastblink" }, "celebrate": true }`
  - **夜用**: `{ "night": { "from": "21:00", "to": "07:00", "brightness": 10 }, "ask": { "color": [255, 140, 0], "mode": "breathe" } }`（夜は暗く、出番も点滅しない）
  - **集中**: `{ "brightness": 30, "work": { "color": [0, 0, 0], "mode": "solid" } }`（作業中は消えたまま。終わったときと出番だけ光る）
- 元に戻したいと言われたら、このファイルを消す（または頼まれた項目だけ消す）
- 書き換えたら「次に色が変わるときから反映されます」と伝える。すぐ確かめたいと言われたら、新しい会話で何か頼んでもらう
- 色の名前で頼まれたら、近い色の数字に直して、何色にしたかを伝える（例: 紫 → [128, 0, 255]）
- いつもの色の数字: 作業中の青 [0, 80, 255] breathe、完了の緑 [0, 255, 60] solid、出番の橙 [255, 140, 0] blink（出番の橙は、いつもの色なら1分たつと点滅がゆっくりになるが、色を決めるとゆっくりにならない）

## 既読で消える機能（任意）
緑・橙が点いたあとに、AI のアプリ（Claude・Codex）を前に出してマウスかキーボードを触ると消える機能（Windows。Mac 版は試験中で、Mac のスキルに書いてある）。目の動きは見ない。作業中の青はこの機能では消えない。
- オンにする前に必ず説明する: 「どのアプリが前にあるか」と「最後に触った時刻」だけを見る。押したキーの中身は見ない・記録しない。パソコン起動時に自動で動く。
- **おすすめは「使う」**。使わないと、緑・橙を消す方法はランプの先のタッチに触れることだけになる（次の作業を頼めば青に変わり、会話を閉じれば消える）。
- ユーザーが同意したら `watch-install.ps1 -Seen on` を実行する。やめたいときは `watch-install.ps1 -Seen off`（常駐の係は残して、既読で消える機能だけ止める。係は合図をすぐランプに送る仕事もしているので、止めると光るのが遅くなる）。ランプの設定を全部外すときだけ `watch-uninstall.ps1`。
- 常駐の係（v0.8〜）: `%USERPROFILE%\.cache\ai-lamp\watch\lamp-watch.ps1` がパソコン起動時から動き、合図係（Codex のフックが呼ぶ `bin\lamp-hook.exe`）が受付箱 `queue` に置いた合図をすぐランプに送る。events.log の `via=queue` はこの道、`via=direct` は PowerShell を毎回起動する道（遅い）
- Claude のデスクトップアプリ以外（VS Code やターミナル）で Claude Code を使っている場合は、
  `%USERPROFILE%\.cache\ai-lamp\watch-apps.txt` に、対象アプリの名前を1行に1つ書く（.exe なし）。
  例: `Code`（VS Code）/ `WindowsTerminal`。最初から `claude`・`ChatGPT`（Codex アプリの中身の名前）・`Codex` は対象なので、書くのはそれ以外だけ。
  書いたあと `watch-install.ps1 -Seen keep` を実行して係を起動し直す。
  アプリ名が分からないときは、そのアプリを前に出した状態で `Get-Process` などで確かめる。

## 入れて／外して／Codex でも使いたい と言われたら
配布リポジトリ https://github.com/kisimenn/ai-lamp の README.md に、ダウンロードから設定までの手順がある。**README の手順どおりに進める**（スクリプトを自分で書かない）。案内は README の「案内のしかた」のとおり（画像と操作の説明は一緒に出し、返事を待つのは操作が終わったときだけ）。
ダウンロード先 `%USERPROFILE%\.cache\ai-lamp\src\ai-lamp-main` のいちばん上に、まとめて設定する `setup.ps1` と、まとめて外す `uninstall.ps1` がある。
- 入れる: `powershell -NoProfile -ExecutionPolicy Bypass -File "<そのフォルダ>\setup.ps1"` を実行する。
  「既読で消える機能」を使いたいと言われていれば `-Watch`、やめたいなら `-NoWatch` を付ける（上の説明をしてから）。
  Codex が入っていれば Codex 用のフックも自動で入る（不要なら `-NoCodex`）。
- 外す: 同じフォルダの `uninstall.ps1` を実行する。
- どちらも、最後に**実際に設定したアプリだけ**を終了して開き直すよう伝える（Claude Code が入っていなければ Claude の開き直しは求めない）。Codex アプリは右上の × では裏で動き続けることがあるので「ファイル → ChatGPT を終了」で終了してもらう（Codex でもメニューには ChatGPT と出る、と一言添える）。開き直したら、設定の会話に戻って「開き直した」と送ってもらう。そのあと**新しい会話**で「こんにちは」と送ってもらい、光るか確かめる（送ったあとに青、返事が終わると緑。返事が早いと青は一瞬。10 秒たっても光らなければ「ランプが光らないとき」の 0 から）。setup の最後の「緑 2 秒」は「ランプが見つかった」確認で、AI との連動の確認ではない。この2つを混ぜて「連動も確認済み」と言わない。
- 設定の結果は「成功（OK）」「飛ばした（--）」「失敗（NG）」を区別して伝える。
- Codex は、入れたあとランプのフックを承認しないと動かない（承認するまで黙って飛ばされる）。必ず伝える。案内は実際の画面に合わせる: 「入力欄の下に出る、黄色い点付きのフックのアイコン →『フックの確認』で、`lamp.ps1` と書かれたランプ用のフックを許可。全部ランプ用なら『すべて許可』、ほかのフックも並んでいれば**ランプ用だけ**選んで『選択した項目を許可』。これで完了、設定画面でもう一度操作する必要はない」。アイコンのとなりの文字（例:「代わりに承認」）は Codex の許可の設定によって変わるので、目印にしない。アイコンが出ないときは、承認済みの場合と未承認の場合があるので、設定 → Hooks で確かめてもらう（決めつけない）。ターミナルの Codex は `/hooks`。**同じ承認を二か所で求めない。許可済みと分かったら何度も頼まない**。setup をやり直すとフックを書き直すので、もう一度承認が必要になることがある。アイコンの画像はリポジトリの `docs/hook-icon.png`。案内するときは、この画像をユーザーに開いて見せるとよい。 Codex のデスクトップアプリの中身の名前は ChatGPT（見張りは最初から対象にしている）
- ダウンロードできないときは、すでに入っているプラグインの scripts（`${CLAUDE_PLUGIN_ROOT}/scripts`）にある
  `codex-install.ps1` / `codex-uninstall.ps1` / `watch-install.ps1` / `watch-uninstall.ps1` を個別に使ってよい。

- 青が点くまで遅いと言われたら、原因を決めつけず `%USERPROFILE%\.cache\ai-lamp\events.log` を見る。1行に合図の時刻・`<n>ms`（ランプ処理の時間）・`boot=<n>ms`（PowerShell の起動にかかった時間）が書いてある。どちらも短いのに遅いなら、AI のアプリがフックを呼ぶまでに時間がかかっている（ログの範囲外なので断定しない）。

## 使える AI
- Claude Code（デスクトップアプリ・ターミナル・VS Code）、Codex（アプリ・ターミナル・VS Code）
- クラウドで動く版（Web の Claude Code、Codex のクラウド）は、パソコンの USB に届かないので使えない
- Codex で橙になるのは「許可を求められたとき」だけ（Codex にはエラーで止まった合図が無い）。Claude Code は許可・選択肢の質問・エラーで橙
- AI が返事の文章の中で質問したときは、どちらも「返事が終わった」扱いで緑になる

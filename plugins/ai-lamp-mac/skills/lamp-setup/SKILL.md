# AI通知ランプの設定と確認（Mac）

このプラグインは、Claude Code のフックから USB ランプに状態を送る。
色は 3 つ: 作業中=青（ゆっくり明るくなったり暗くなったり）/ 完了=緑の点灯 / あなたの出番（許可・質問・エラーで止まった）=橙の点滅。
ランプの先の**タッチ**（光る所のまわり）に触れると、どの状態でも消える（設定は消えない）。お客さんに話すときも「タッチ」と呼ぶ。

ユーザーは機械に詳しくないことが多い。専門用語を避け、やさしい日本語で説明する。
この Mac 版は、実機の Mac での確認がまだ十分でない版。うまく動かないときは、何が起きたかを具体的に聞いて、原因を一緒に探す。
「既読で消える機能」は v0.8.2 で Mac 版にも入れたが、**Mac の実機ではまだ試していない（試験中）**。緑・橙が点いたあとに、Claude か Codex（ChatGPT）を前に出してマウスかキーボードを触ると消える。見るのは「いちばん前のアプリの名前」（lsappinfo）と「最後に触ってから何秒たったか」（ioreg）だけ。押したキーの中身は見ない。
- 入れる: `/usr/bin/perl ${CLAUDE_PLUGIN_ROOT}/scripts/watch-install.pl`（`~/Library/LaunchAgents/local.ai-lamp.watch.plist` を置いて動かす。Mac が「バックグラウンド項目が追加されました」と通知することがある、と先に伝える）。外す: `watch-install.pl --uninstall`。一時的に止めるだけなら `~/.cache/ai-lamp/seen-off` を作る
- 動作の記録は `~/.cache/ai-lamp/watch.log`。対象のアプリを足すときは `~/.cache/ai-lamp/watch-apps.txt` に 1 行 1 つ書いて、watch-install.pl を実行し直す
- **おすすめは「使う」**。使わないと、緑・橙を消す方法はランプの先のタッチに触れることだけになる

## スクリプトの場所
- 送信: `/usr/bin/perl ${CLAUDE_PLUGIN_ROOT}/scripts/lamp.pl <work|done|ask|end|seen>`（`error` を渡すと `ask` と同じ橙）
- 状態の記録: `~/.cache/ai-lamp/state.json`（`sent` が最後にランプへ送った状態、`port` が見つけたポート）
- ランプは `/dev/cu.usbmodem*` として見える。「ID?」と送ると「AILAMP …」と答えるものがランプ。

## ランプがつながっているか確かめる（まずこれを使う）
`/usr/bin/perl ${CLAUDE_PLUGIN_ROOT}/scripts/lamp.pl test` を実行する。ランプを探して、見つかれば 2 秒緑に光らせて消し、結果を日本語 1 行で表示する。**表示された結果を、そのままユーザーに伝える**。NG のときは `/usr/bin/perl ${CLAUDE_PLUGIN_ROOT}/scripts/lamp.pl diag` で、Mac がランプをどこまで認識しているか（見つけたか・通信の係が付いたか・通信の口ができたか・書き込み待ちか）を調べ、その結果もそのまま伝える。test の結果に「（AI へ）」の案内があれば、そのとおりに案内する（光るのに見つからないときは、たいてい Mac の「アクセサリの接続を許可」。設定を変えるのはお客さんで、AI は変えない）。

## ランプが光らないとき（上から順に確認）
0. **まず記録を見て切り分ける**（お客さんの操作は要らない。読むだけ）: `~/.cache/ai-lamp/events.log` の最後の 10 行ほどを読む。会話の中身は書かれていない（合図の種類・会話番号の先頭・結果・時間だけ）。
   - 光らなかった時刻の行が**増えていない** → AI からの合図が出ていない。アプリを「×」でなくメニューの「終了」で閉じて開き直したか、新しい会話で試したか、（Codex は）フックを承認したかを確かめる
   - 行はあるが `send=NG(...)` → 合図は出ているが、ランプに届いていない。下の 1 から確かめる
   - `send=ok(...)` なのに光っていない → ランプ本体か USB の口の問題のことがある。別の USB の口に挿してもらう
1. ランプが USB に挿さっているか。挿し直すと虹色が一瞬流れれば本体は正常。
   Mac は初めて挿したとき「アクセサリの接続を許可しますか？ AI Lamp をこの Mac に接続しますか？」と出る。「許可しない」を押していると通信できないので、挿し直して「許可」を押してもらう。
2. `ls /dev/cu.usbmodem*` でランプのポートが出るか。出なければ、ケーブルをデータ通信できるものに替える・別の差し込み口を試す。
3. `state.json` を読み、`port` と `sent` を確認する。`sent` が空（null）ならランプが見つかっていない。
4. ランプへの送信を試す: `echo '{}' | /usr/bin/perl ${CLAUDE_PLUGIN_ROOT}/scripts/lamp.pl done` を実行し、緑になるかユーザーに聞く。
   手で試したあとは `state.json` を消す（`default` という試験用の記録が残り、本物の表示を邪魔するため）。
5. 他のソフト（Arduino IDE のシリアルモニタなど）が同じポートを開いていないか。開いていると送れない。
6. それでも光らないときは、ターミナルで `AI_LAMP_PORT=/dev/cu.usbmodemXXXX` を決め打ちして試す、または出た結果をユーザーに見せてもらう。

## 光り方を変えて と言われたら（色・光り方・明るさ）
スクリプトは書き換えない。**好みのファイル `~/.cache/ai-lamp/colors.json` だけ**を書き換える（無ければ作る。UTF-8 の JSON）。
```json
{
  "brightness": 50,
  "work": { "color": [128, 0, 255], "mode": "breathe" },
  "done": { "color": [255, 255, 255], "mode": "solid" },
  "ask":  { "color": [255, 0, 0], "mode": "blink" }
}
```
- `work`＝作業中、`done`＝完了、`ask`＝あなたの出番。書かなかった状態は、いつもの色（青・緑・橙）のまま
- `color` は赤・緑・青の強さ（各 0〜255）、または `"rainbow"`（虹色が流れ続ける）。`mode` は `solid`（点灯）／`breathe`（ゆっくり明るくなったり暗くなったり）／`blink`（点滅）／`fastblink`（激しい速い点滅）
- `"rainbow"` と `fastblink` はランプのファーム v1.0 から（`ID?` の返事が `AILAMP 1.0` 以上）。古いランプでは色が変わらないので、そのときは「ランプが古い版のため、この光り方は使えません」と伝える
- `brightness` は全体の明るさ（1〜100、％）。書かなければ最大
- ほかに使える項目（どれも、頼まれたときだけ書く。書かなければ使わない）
  - **夜は暗く**: `"night": { "from": "22:00", "to": "07:00", "brightness": 20 }`（その時刻の間だけ明るさを変える。日をまたいでよい。色が変わるときに反映されるので、夜に入っても点きっぱなしの色はそのまま）
  - **終わったときにお祝い**: `"celebrate": true`（返事が終わった瞬間に 1.5 秒だけ虹色が光ってから、完了の色になる）
  - **長い作業の目安**: `"long_work": { "minutes": 10, "color": [160, 0, 255] }`（作業中がこの時間続いたら、作業中の色をこの色に変える）
  - **AI ごとに色を分ける**: `"codex": { "work": { "color": [255, 0, 255], "mode": "breathe" } }`、`"claude": { ... }`（その AI のときだけ使う色。書いていない状態はふつうの色）
  - お祝い・長い作業は、ランプのファーム v1.1 から（`ID?` の返事が `AILAMP 1.1` 以上）。虹色・速い点滅は v1.0 から
- **おまかせセット**（「やさしい光り方にして」などと頼まれたら、このとおりに書く。今の設定は上書きしてよいか一言確かめる）
  - **いつもの**: ファイルを消す
  - **やさしい**: `{ "brightness": 40, "work": { "color": [0, 80, 255], "mode": "breathe" }, "done": { "color": [0, 255, 60], "mode": "breathe" }, "ask": { "color": [255, 140, 0], "mode": "breathe" } }`（全部ゆっくり、暗め）
  - **派手**: `{ "brightness": 100, "work": { "color": "rainbow", "mode": "solid" }, "ask": { "color": [255, 0, 0], "mode": "fastblink" }, "celebrate": true }`
  - **夜用**: `{ "night": { "from": "21:00", "to": "07:00", "brightness": 10 }, "ask": { "color": [255, 140, 0], "mode": "breathe" } }`（夜は暗く、出番も点滅しない）
  - **集中**: `{ "brightness": 30, "work": { "color": [0, 0, 0], "mode": "solid" } }`（作業中は消えたまま。終わったときと出番だけ光る）
- 元に戻したいと言われたら、このファイルを消す（または頼まれた項目だけ消す）
- 書き換えたら「次に色が変わるときから反映されます」と伝える。すぐ確かめたいと言われたら、新しい会話で何か頼んでもらう
- 色の名前で頼まれたら、近い色の数字に直して、何色にしたかを伝える（例: 紫 → [128, 0, 255]）
- いつもの色の数字: 作業中の青 [0, 80, 255] breathe、完了の緑 [0, 255, 60] solid、出番の橙 [255, 140, 0] blink（出番の橙は、いつもの色なら1分たつと点滅がゆっくりになるが、色を決めるとゆっくりにならない）

## 入れて／外して／Codex でも使いたい と言われたら
配布リポジトリ https://github.com/kisimenn/ai-lamp の README.md に、ダウンロードから設定までの手順がある。**README の手順どおりに進める**（スクリプトを自分で書かない）。案内は README の「案内のしかた」のとおり（画像と操作の説明は一緒に出し、返事を待つのは操作が終わったときだけ）。
ダウンロード先 `~/.cache/ai-lamp/src/ai-lamp-main` のいちばん上に、まとめて設定する `setup.sh` と、まとめて外す `uninstall.sh` がある。
- 入れる: そのフォルダの `bash setup.sh --watch` を実行する（既読で消える機能を使わないなら `--no-watch`）。
  先に「Claude と Codex のどちらで使うか」を聞き、使わない方は飛ばす（Claude だけなら `--no-codex`、Codex だけなら `--no-claude`）。
  実行する**前に**「設定の最後に、確認のためランプが緑に 2 秒光ります。ランプを見ていてください」と予告する（実行したあとでは遅い）。
  Codex が入っていれば Codex 用のフックも自動で入る。
- 外す: 同じフォルダで `bash uninstall.sh` を実行する。
- どちらも、最後に**実際に設定したアプリだけ**を終了して開き直すよう伝える（Claude Code が入っていなければ Claude の開き直しは求めない）。アプリは command キーを押したまま Q を押すと終了できる（左上の赤い丸では動き続けることがある）。開き直したら、設定の会話に戻って「開き直した」と送ってもらう。そのあと**新しい会話**で「こんにちは」と送ってもらい、光るか確かめる（送ったあとに青、返事が終わると緑。返事が早いと青は一瞬。10 秒たっても光らなければ「ランプが光らないとき」の 0 から）。setup の最後の「緑 2 秒」は「ランプが見つかった」確認で、AI との連動の確認ではない。この2つを混ぜて「連動も確認済み」と言わない。
- 設定の結果は「成功（OK）」「飛ばした（--）」「失敗（NG）」を区別して伝える。
- Codex は、入れたあとランプのフックを承認しないと動かない（承認するまで黙って飛ばされる）。必ず伝える。案内は実際の画面に合わせる: 「入力欄の下に出る、黄色い点付きのフックのアイコン →『フックの確認』で、`lamp.pl` と書かれたランプ用のフックを許可。全部ランプ用なら『すべて許可』、ほかのフックも並んでいれば**ランプ用だけ**選んで『選択した項目を許可』。これで完了、設定画面でもう一度操作する必要はない」。アイコンのとなりの文字（例:「代わりに承認」）は Codex の許可の設定によって変わるので、目印にしない。アイコンが出ないときは、承認済みの場合と未承認の場合があるので、設定 → Hooks で確かめてもらう（決めつけない）。ターミナルの Codex は `/hooks`。**同じ承認を二か所で求めない。許可済みと分かったら何度も頼まない**。setup をやり直すとフックを書き直すので、もう一度承認が必要になることがある。アイコンの画像はリポジトリの `docs/hook-icon.png`。案内するときは、この画像をユーザーに開いて見せるとよい。
- ダウンロードできないときは、すでに入っているプラグインの scripts（`${CLAUDE_PLUGIN_ROOT}/scripts`）にある
  `codex-install.pl` / `codex-uninstall.pl` を `/usr/bin/perl` で個別に使ってよい。

## 使える AI
- Claude Code（デスクトップアプリ・ターミナル・VS Code）、Codex（アプリ・ターミナル・VS Code）
- クラウドで動く版（Web の Claude Code、Codex のクラウド）は、パソコンの USB に届かないので使えない
- Codex で橙になるのは「許可を求められたとき」だけ（Codex にはエラーで止まった合図が無い）。Claude Code は許可・選択肢の質問・エラーで橙
- AI が返事の文章の中で質問したときは、どちらも「返事が終わった」扱いで緑になる

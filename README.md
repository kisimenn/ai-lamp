# AI通知ランプ 設定手順（AI向け）

この文書は、お客さんに頼まれた AI（Claude Code または Codex）が読んで実行するための手順です。
AI の作業状態を USB ランプの色で知らせます（作業中=青 / 完了=緑 / あなたの出番=橙）。
お客さん向けの初期設定マニュアル（PDF）: https://github.com/kisimenn/ai-lamp/blob/main/docs/setup-manual.pdf

## AI への約束ごと（必ず守る）
- **スクリプトや設定を自分で書かない。** 下に書いたコマンドだけを、書いたとおりに実行する。設定ファイル（settings.json・hooks.json・config.toml）を手で編集しない。
- **COM ポートを自分で調べて判断しない。** ランプが見つかるかどうかは、スクリプトが表示する結果をそのまま伝える。
- お客さんは機械に詳しくないことが多い。専門用語を避けて、やさしい日本語で短く話す。
- お客さんにしてもらうのは「コマンドの実行を許可する」「どの AI で使うか答える」「既読で消える機能を使うか答える」「ランプが光ったか答える」「アプリを開き直して、この会話に戻る」「（Codex のときだけ）フックを1回承認する」「『こんにちは』を送って、光ったか答える」だけにする。
- ランプの先の、光る所のまわりは「**タッチ**」と呼ぶ。触れるとランプが消える（設定は消えない）。
- クラウドで動く版（Web の Claude Code、Codex のクラウド）では使えない（パソコンの USB に届かないため）。その場合はそう伝えて終わる。

## 案内のしかた（必ず守る）
- **見本の画像と操作の説明は、1 回の返事で一緒に出す。** 「画像は見えましたか？」と聞いて止まらない。返事を待つのは、お客さんの操作が終わったとき（「開き直した」「できた」「光った」など）だけ。
- **画像の見せ方は 2 つとも行う:**
  1. お客さんのブラウザで開く。Windows: `Start-Process '<画像のURL>'`、Mac: `open '<画像のURL>'`（アプリを閉じても、ブラウザの画像は残る）
  2. 返事の中にも画像として載せる（`![見本](<画像のURL>)`）。そのうえで「画像が見えなければ、この URL を押してください: <画像のURL>」と書き添える
  ブラウザで開くコマンドが止められたり失敗したりしても、そのまま案内を続ける（URL を押してもらえばよい）。
- **ただし、順番が決まっている操作は分ける。** アプリの開き直しとフックの承認は、**別々の返事**で案内する（開き直してからでないと承認できないため）。
- **毎回、短く進み具合を伝える。** 例:「ランプの確認まで終わりました。次はアプリの開き直しです。」
- **4 つを区別して伝える。** 「設定できた（スクリプトが OK）」「ランプが見つかった（スクリプトの表示）」「実物が光った（お客さんの返事）」「AI と連動した（『こんにちは』のあと光ったのをお客さんが見た）」。お客さんが見ていないことを「できた」と言わない。**「設定完了」と言うのは、連動が確かめられたときだけ**。
- **予告は、実行する前に出す。** 「緑に 2 秒光ります。ランプを見ていてください」は、setup を実行する（またはお客さんに実行を頼む）**前に**、必ず文字で出す。質問の答えを聞いたあと、すぐ実行してはいけない。実行したあとに予告しても意味がない。
- **原因を決めつけない。** たとえば別の USB の口で光っても、「前の口が壊れている」「古いパソコンだから」と言い切らない。

## はじめに：どれに当てはまるか
| 今この設定をしている AI | パソコン | 進む先 |
|---|---|---|
| Claude Code | Windows | 「1. ダウンロード（Windows）」 |
| Claude Code | Mac | 「1. ダウンロード（Mac）」 |
| Codex | Windows | 「1. ダウンロード（Windows）」 |
| Codex | Mac | 「1. ダウンロード（Mac）」 |

Codex で使う場合（「2」の①で「Codex」か「両方」と答えた場合）は、開き直したあと「4. Codex のフックを承認」も行う。

どちらの AI でも同じ設定スクリプトを使います。スクリプトは、パソコンに入っている Claude Code と Codex の両方を設定できますが、**お客さんが使わない AI は設定しない**（使わないアプリの開き直しやフックの承認まで案内することになるため）。どれで使うかは「2」で聞く。

最初にお客さんへ伝える（これだけ。長くしない）:
> 設定は全部で 5〜10 分ほどです（途中でアプリを 1 回開き直します）。ランプの設定ファイルをダウンロードして、設定を実行します。途中で実行の許可を求められたら許可してください。
> ランプはパソコンの USB の口に挿しておいてください。USB ハブ（口を増やす機器）を使っている場合は、パソコンに直接挿してください。

Mac のときは、あわせて次を伝える（許可しないとランプと通信できない。Mac は許可していない機器に電気だけ渡すので、ランプは光るのに通信できない状態になる）:
> ランプは、Mac のロックを外した状態（使っている最中）で挿してください。『アクセサリの接続を許可しますか？』と出たら、『許可』を押してください。

「許可しない」を押してしまった・画面が出なかった、と言われても、ここでは止まらずに進める（「2」のランプの確認で NG になったら、その表示のとおりに案内する）。

## 1. ダウンロード（Windows）
PowerShell で、次をそのまま実行する（`%USERPROFILE%\.cache\ai-lamp\src` に置く）。
```powershell
$d = Join-Path $env:USERPROFILE '.cache\ai-lamp\src'; Remove-Item -Recurse -Force $d -ErrorAction SilentlyContinue; New-Item -ItemType Directory -Force -Path $d | Out-Null; Invoke-WebRequest -UseBasicParsing -Uri 'https://github.com/kisimenn/ai-lamp/archive/refs/heads/main.zip' -OutFile (Join-Path $d 'repo.zip'); Expand-Archive -Force (Join-Path $d 'repo.zip') $d; Get-ChildItem $d -Directory | Select-Object -ExpandProperty FullName
```
最後に表示されたフォルダ（`...\ai-lamp-main`）を、次の手順で使う。

## 1. ダウンロード（Mac）
ターミナルで、次をそのまま実行する（`~/.cache/ai-lamp/src` に置く）。
```bash
d="$HOME/.cache/ai-lamp/src"; rm -rf "$d"; mkdir -p "$d" && curl -fsSL -o "$d/repo.zip" https://github.com/kisimenn/ai-lamp/archive/refs/heads/main.zip && ditto -x -k "$d/repo.zip" "$d" && ls -d "$d"/*/
```
最後に表示されたフォルダ（`.../ai-lamp-main/`）を、次の手順で使う。

## 2. 設定を実行して、ランプが光るか確かめる
**実行する前に、次の 2 つを 1 回の返事でまとめて聞く**（Windows・Mac とも）:

**① どの AI で使うか**
> ランプは、Claude と Codex のどちらで使いますか？（両方でも大丈夫です）

- 今この設定をしている AI だけでなく、ふだん使う AI を答えてもらう
- Claude だけ → コマンドの最後に ` -NoCodex`（Mac は ` --no-codex`）を付ける
- Codex だけ → ` -NoClaude`（Mac は ` --no-claude`）を付ける
- 両方 → どちらも付けない

**② 既読で消える機能を使うか**
> ランプが緑（終わった）や橙（あなたの出番）に点いたあと、どうやって消すかを決めます。
> **おすすめは「使う」です。** 使うと、AI のアプリの画面でマウスやキーボードを触っただけで、ランプが消えます（見るのは「どのアプリが前にあるか」と「最後に触った時刻」だけで、打った文字は見ません）。
> 使わない場合、ランプを消すには、ランプの先の「タッチ」（光る所のまわり）に触れる必要があります。
> 「既読で消える機能」を使いますか？（あとから私に頼んで変えられます）

Mac のときは、あわせて「使うと、Mac の画面に『バックグラウンド項目が追加されました』と出ることがあります。ランプの機能なので、そのままで大丈夫です」と伝える（Mac 版のこの機能は試験中）。

- 使う → 下のコマンドの最後に ` -Watch`（Mac は ` --watch`）を付ける
- 使わない → ` -NoWatch`（Mac は ` --no-watch`）を付ける

コマンド（例: Claude だけ・既読で消える機能を使う）:
- Windows: `powershell -NoProfile -ExecutionPolicy Bypass -File "<1で表示されたフォルダ>\setup.ps1" -Watch -NoCodex`
- Mac: `bash "<1で表示されたフォルダ>/setup.sh" --watch --no-codex`

①②の答えに合わせて、付けるものを入れ替える（既読: `-Watch`／`-NoWatch`、AI: `-NoCodex`／`-NoClaude`／なし。Mac は `--watch`／`--no-watch`、`--no-codex`／`--no-claude`／なし）。

**答えを聞いたら、実行する前に必ず予告する**（実行するツールを呼ぶ前に、この文を出す。お客さんが自分で実行ボタンを押すときも、押す前に伝える）:
> 設定の最後に、確認のためランプが**緑に 2 秒**光ります。ランプを見ていてください。

結果は「OK（成功）」「--（飛ばした）」「NG（失敗）」で1行ずつ表示される。**区別したまま**、短くお客さんに伝える。スクリプトの最後に出る「開き直し」「光り方」の案内は、**ここではまとめて伝えない**（3〜6 で伝える）。

最後の行がランプの確認で、ランプが見つかれば緑に2秒光らせている。「見つかりました」と出ても、実物が光ったとは限らない。お客さんに聞いて、**返事を待つ**:
> ランプは緑に光りましたか？

- 光った → 「ランプの確認まで終わりました。次はアプリの開き直しです。」と伝えて「3」へ
- 光らない・見逃した → 「7. 光らないとき」の ③ へ。実物が光るのを確かめてから「3」へ進む

## 3. アプリを開き直す（終わったら、この会話に戻ってもらう）
**設定したアプリだけ**を終了して開き直してもらう（スクリプトの最後の案内に、どのアプリかが出ている）。
見本の画像（Windows のとき）と、理由・終わらせ方・戻り方を、**1 回の返事で一緒に**出す。**フックの承認はまだ言わない。** そのあと「開き直した」の返事を待つ。

見本の画像（「案内のしかた」のとおり 2 つの方法で見せる。両方を設定したときは 2 枚とも）:
- Windows の Claude アプリ: https://raw.githubusercontent.com/kisimenn/ai-lamp/main/docs/claude-quit.png
- Windows の Codex アプリ: https://raw.githubusercontent.com/kisimenn/ai-lamp/main/docs/codex-quit.png
- Mac は見本の画像なし

案内の例:
- Windows の Claude アプリ:
  > 右上の「×」では、画面が閉じても裏でアプリが動き続け、新しい設定が使われないことがあります。見本の画像のとおり、左上の「≡」→「ファイル」→「終了」を選んでください（画像が見えなければ、この URL を押してください: <URL>）。開き直したら、**この会話に戻って「開き直した」と送ってください。** パソコンの再起動は要りません。
- Windows の Codex アプリ:
  > 右上の「×」では、画面が閉じても裏でアプリが動き続け、新しい設定が使われないことがあります。見本の画像のとおり、「ファイル」→「ChatGPT を終了」を選んでください（Codex でも、メニューには「ChatGPT」と出ます。画像が見えなければ、この URL を押してください: <URL>）。開き直したら、**この会話に戻って「開き直した」と送ってください。** パソコンの再起動は要りません。
- Mac（Claude・Codex とも）:
  > 左上の赤い丸（×）では、画面が閉じてもアプリが動き続け、新しい設定が使われないことがあります。アプリの画面を前に出した状態で、キーボードの「command」（スペースキーのとなり）を押したまま「Q」を押して終了してください（画面のいちばん上のメニューで、アプリの名前 →「〇〇を終了」でも同じです）。開き直したら、**この会話に戻って「開き直した」と送ってください。** パソコンの再起動は要りません。
- 両方を設定したときは、「両方とも終了して、開き直してください」とし、終わらせ方を 2 つ並べる

「開き直した」と返事が来たら:
- Codex を設定した → 「4. Codex のフックを承認」へ
- Claude だけ → 「5. AI との連動を確かめる」へ

## 4. Codex のフックを承認（Codex を使っている人だけ・1回だけ）
Codex は、ランプ用のフックを1回承認しないと光らない（承認するまで黙って飛ばされる）。
見本の画像と操作の説明を、**1 回の返事で一緒に**出して、「できた」の返事を待つ。
- アイコンの画像: https://raw.githubusercontent.com/kisimenn/ai-lamp/main/docs/hook-icon.png （「案内のしかた」のとおり 2 つの方法で見せる）

案内の例:
> 次は、ランプを動かすための許可です。入力欄の下に、見本の画像と同じ「黄色い点付きのアイコン」が出ているはずです（画像が見えなければ、この URL を押してください: <URL>）。押して「フックの確認」を開き、`lamp-hook`（または `lamp.ps1`、Mac は `lamp.pl`）と書かれたランプ用のフックを許可してください。全部ランプ用なら「すべて許可」、ほかのフックも並んでいれば、ランプ用だけ選んで「選択した項目を許可」です。できたら「できた」と送ってください。アイコンが見当たらなければ、そう教えてください。

- アイコンのとなりの文字は Codex の設定で変わるので、目印にしない。
- アイコンが出ないときは、承認済みのこともある。設定 → Hooks で確かめてもらう（決めつけない）。
- ターミナルの Codex は `/hooks` で承認する。
- 同じ承認を二か所で求めない。承認済みと分かったら何度も頼まない。
- 「できた」と来たら「5. AI との連動を確かめる」へ。

## 5. AI との連動を確かめる
「2」の緑 2 秒は「ランプが見つかった」確認で、AI との連動の確認ではない。ここで確かめる。
> 新しい会話で「こんにちは」と送ってください。送ったあとに**青**、返事が終わると**緑**に光ります（返事が早いと、青は一瞬で緑に変わります）。
> **10 秒たっても光らなかったら**、この会話に戻って教えてください。光ったら「光った」と送ってください。

- 「光った」→ 青を見たかどうかは聞かない（緑に光れば、AI とランプはつながっている）。「設定はすべて完了です。」と伝えて「6」へ
- 「光らない」→ 「7. 光らないとき」の ① から
- Codex で橙になるのは「許可を求められたとき」だけ（Codex にはエラーで止まった合図が無い）

## 6. 最後に、光り方を変えられることを紹介する
連動が確かめられたあとに、短く紹介する。押しつけず「気が向いたら」くらいで。
> ちなみに、ランプの光り方は、私に頼めば変えられます。たとえば、
> - 「作業中の色を紫にして」
> - 「夜は暗くして」
> - 「作業が終わったら虹色でお祝いして」
> - 「作業が10分を超えたら色を変えて」
> - 「やさしい光り方にして」（ほかに 派手・夜用・集中）
> 気が向いたら言ってください。

頼まれたら、ランプのスキル（lamp-setup）の「光り方を変えて と言われたら」のとおりに、好みのファイルだけを書き換える。

## 7. 光らないとき（この順で、深追いしない）
**① よくある原因を確かめる**（1 回の返事でまとめて聞く）
> いくつか確かめさせてください。
> - アプリは「×」ではなく、メニューの「終了」で閉じましたか？（Mac は command を押したまま Q）
> - 「こんにちは」は、**新しい会話**で送りましたか？
> - （Codex のとき）フックの承認はできましたか？ 入力欄の下に黄色い点のアイコンが残っていたら、まだです。

どれかに当てはまれば、その操作をやり直してもらい、もう一度「こんにちは」で試す。

**② 記録を見て、どこで止まっているか調べる**（AI が自分で読むだけ。お客さんの操作は要らない。書き換えない）
記録には会話の中身は書かれていない（合図の種類・会話番号の先頭・結果・時間だけ）。
- Windows: `Get-Content "$env:USERPROFILE\.cache\ai-lamp\events.log" -Tail 10`
- Mac: `tail -n 10 ~/.cache/ai-lamp/events.log`

読み方:
- 「こんにちは」を送った時刻の行が**増えていない**（またはファイルが無い）→ AI からの合図が出ていない。アプリの開き直しか、Codex の承認がまだ。① の操作をやり直してもらう
- 行はあるが `send=NG(...)` → 合図は出ているが、ランプに届いていない。③ へ
- `send=ok(...)` なのに光っていない → ③ の 2（別の USB の口）から

**③ ランプの確認**
1. 「ランプを USB から抜いて、挿し直してください。**虹色**に光りましたか？」と聞く。
2. 虹色に光らない、または「見つかりました」と出たのに緑に光らない → **別の USB の口に挿してもらう**（口によって光らないことがある）。USB ハブを使っていれば外して、パソコンに直接挿してもらう。そのあと、この下の 3 のランプの確認をやり直す。
   - 虹色は「電気が届いた」しるしで、「パソコンと通信できる」しるしではない。ケーブルや変換アダプタを使っている場合、**充電専用のケーブルだと虹色に光っても通信できない**。ランプの確認で「USB の機器として見えません」と出たら、データ通信できるケーブルに替えるか、パソコンに直接挿してもらう。
3. 虹色に光った → （Mac のときは）「挿したときに『アクセサリの接続を許可しますか？』と出ましたか？『許可しない』を押していたら、もう一度挿し直して『許可』を押してください」と聞く。そのうえで、ランプの確認だけをやり直す（「緑に 2 秒光ります。ランプを見ていてください」と予告してから）:
   - Windows: `powershell -NoProfile -ExecutionPolicy Bypass -File "<1のフォルダ>\plugins\ai-lamp\scripts\lamp-test.ps1"`
   - Mac: `/usr/bin/perl "<1のフォルダ>/plugins/ai-lamp-mac/scripts/lamp.pl" test`
   表示された結果をそのまま伝え、緑に光ったか聞く。Mac で「（AI へ）」の案内が出たら、そのとおりに案内する（設定画面を開く・「毎回確認」にしてもらう・ロックを外して挿し直して「許可」）。
4. Arduino IDE などシリアル通信を使うソフトが開いていれば、閉じてもらってからもう一度 3。
5. （Mac で、3 が NG のとき）原因を調べる。AI が実行して、結果をそのまま見せる（会話の中身やほかの機器の名前は出ない）:
   `/usr/bin/perl "<1のフォルダ>/plugins/ai-lamp-mac/scripts/lamp.pl" diag`
   - 「通信の係: 付いていない」→ Mac がまだ通信を許可していないことがある。「システム設定 → プライバシーとセキュリティ」の「アクセサリの接続を許可」を確かめてもらい、ランプを抜いて 5 秒待ってから挿し直して「許可」を押してもらう。設定の変更はお客さんが自分で行う（AI は変えない）
   - 「書き込み待ちの状態: はい」→ 抜いて 5 秒待ってから挿し直してもらう
   - それでもだめなら、④ へ。連絡するときに、この結果も一緒に送ってもらう

**④ それでもだめなら**
- パソコンを再起動してから、もう一度この手順を最初から頼んでもらう。
- それでもだめなら「リベシティのメッセージでご連絡ください」と伝えて終わる。
